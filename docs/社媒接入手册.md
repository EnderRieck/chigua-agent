# 社媒接入手册

吃瓜智能体一共接五类信息源：联网搜索（DeepSeek）、微博、知乎、小红书、X。本手册说明每一路是怎么实现的、需要什么凭证、凭证怎么拿、出问题怎么查。所有凭证只写在项目根目录的 `.env` 里，该文件已在 `.gitignore` 中，不会被提交。

## 一、本项目的实现

四个社交平台都没有面向个人开发者的官方搜索 API，本项目采用**自研轻量适配器 + 可选挂接 MCP** 的方式，每一路都有降级链：主路径不可用时自动退到下一级，并把原因写进证据说明，分析员据此判断可信度。

| 平台 | 主路径 | 需要的凭证 | 降级链 |
|---|---|---|---|
| 联网搜索 / 网页抓取 | DeepSeek Search / Fetch API（`/v1/tools/search`、`/v1/tools/fetch`） | `DEEPSEEK_API_KEY` | — |
| LLM 编排 | Grok（OpenAI 兼容协议，可经中转站） | `XAI_API_KEY`、`XAI_BASE_URL`、`XAI_MODEL` | — |
| 微博热搜 | 直连 `weibo.com/ajax/side/hotSearch` | `WEIBO_COOKIE` | → 公开镜像 60s API（免凭证） |
| 微博搜索 | 直连桌面端 `s.weibo.com` 搜索页并解析 HTML，支持 综合 / 热门 / 实时 | `WEIBO_COOKIE` | → DeepSeek `site:weibo.com` |
| 知乎热榜 | 公开接口 `api.zhihu.com/topstory/hot-list` | 无 | — |
| 知乎搜索 / 问题回答 | 直连 `api/v4/search_v3`、`questions/{id}/answers`，本地计算 x-zse-96 签名（`chigua/tools/zhihu_sign.py`） | `ZHIHU_COOKIE` | → DeepSeek `site:zhihu.com` |
| 小红书搜索 / 笔记详情 | 本地运行的 [xiaohongshu-mcp](https://github.com/xpzouying/xiaohongshu-mcp)，经 MCP 协议调用 `search_feeds`、`get_feed_detail` | `XHS_MCP_URL`（扫码登录一次） | → DeepSeek `site:xiaohongshu.com` |
| X | xAI Responses API 的服务端工具 `x_search` | 复用 `XAI_API_KEY` | → Grok Live Search → DeepSeek `site:x.com` → 转述 X 舆论的报道 |

设计原则：

1. **不绕过平台风控。** 微博对匿名访问返回 432 或跳转登录页，本项目不伪造访客身份，只用公开镜像、公开接口、用户本人的 Cookie、用户本人扫码登录的会话。
2. **拒绝幻觉帖子。** X 的两条模型侧链路都要求接口返回真实引用，否则判定为未真正联网并降级。
3. **所有来源统一进证据库并编号。** 分析员必须用 `[E#]` 引用，报告自动附来源列表。

## 二、各平台凭证获取教程

### 2.1 Grok（LLM 编排 + X 搜索）

**官方直连：** 到 [console.x.ai](https://console.x.ai) 注册并创建 API Key，`.env` 填：

```
XAI_API_KEY=xai-xxxx
XAI_BASE_URL=https://api.x.ai/v1
XAI_MODEL=grok-4.3
```

**国内中转站：** 在中转站后台创建 Key，注意几点：

- `XAI_BASE_URL` 填到 `/v1` 为止，**不要**带 `/chat/completions`。填错了程序会自动剥掉多余后缀，但最好一开始就填对。
- `XAI_MODEL` 以中转站的模型列表为准。有的中转站按"分组"划分可用模型，Key 所在分组没有 Grok 时会报 `No available channel for model`，需要换一个分组的 Key。
- X 搜索依赖 xAI 的 Responses API（`/v1/responses`）。实测有的中转站支持，有的不支持；不支持时自动降级，不影响其他功能。确定不支持的话把 `X_SEARCH_MODE` 设为 `deepseek` 可以省掉两次失败请求。

验证：`pixi run doctor` 里"LLM 对话"一行应显示 `回复: 'ok'`；加 `--full` 可实测 X 搜索链路。

### 2.2 DeepSeek（联网搜索）

1. 打开 [platform.deepseek.com](https://platform.deepseek.com)，注册并登录。
2. 左侧 **API keys** → **创建 API key**，复制生成的 `sk-` 开头字符串（只显示一次）。
3. 左侧 **充值** 保证有余额。Search 与 Fetch 各 0.75 美元 / 千次成功请求，2026 年 11 月 1 日起计费，失败和空结果不收费。
4. `.env` 填：

```
DEEPSEEK_API_KEY=sk-xxxx
DEEPSEEK_BASE_URL=https://api.deepseek.com
```

验证：`pixi run doctor` 里"DeepSeek Search"一行显示 `返回 N 条`。401 是 Key 错，402 是余额不足。

### 2.3 微博 Cookie

不填也能用：热搜走公开镜像，搜索走 DeepSeek。填了之后热搜多出标签和分类字段，搜索能直接拿到每条微博的转发、评论、点赞和永久链接，质量明显更高。

**获取步骤（Chrome / Edge / Safari 通用）：**

1. 浏览器登录 **weibo.com**（桌面版，不是 m.weibo.cn）。
2. 按 `Cmd + Option + I`（Windows 是 `F12`）打开开发者工具，切到 **Network / 网络** 标签。
3. 刷新页面，在请求列表里点任意一个发往 `weibo.com` 的请求，例如名字以 `ajax` 开头的。
4. 右侧 **Headers / 标头** → **Request Headers** → 找到 `Cookie:` 这一行，右键复制整段值。它很长，通常包含 `SUB=`、`SUBP=`、`XSRF-TOKEN=` 等字段。
5. `.env` 填入，原样粘贴在等号后面，一行写完，不要加引号：

```
WEIBO_COOKIE=XSRF-TOKEN=xxx; SCF=xxx; SUB=xxx; SUBP=xxx; ALF=xxx; WBPSESS=xxx
```

验证：`pixi run doctor` 里"微博热搜"显示 `直连，实时`，"微博 Cookie 搜索"显示 `直连，综合`。

注意：

- 必须是桌面端 weibo.com 的 Cookie。手机端 m.weibo.cn 的登录态是另一套，桌面 Cookie 对它无效，这也是本项目改走 s.weibo.com 搜索页的原因。
- Cookie 一般几周到几个月过期，过期后自检会报 302 跳转或 403，重新复制一次即可。

### 2.4 知乎 Cookie

不填也能用：热榜免登录，搜索走 DeepSeek。填了之后可以直连站内搜索（0.9 秒返回，带赞同数和 question_id）和读取问题下的高赞回答正文。

**获取步骤：**

1. 浏览器登录 **zhihu.com**。
2. 打开开发者工具 → **Network** 标签，刷新页面。
3. 点任意一个发往 `zhihu.com` 的请求（例如 `api/v4/...` 开头的），在 **Request Headers** 里复制整段 `Cookie:` 的值。
4. 确认里面包含 **`d_c0`** 和 **`z_c0`** 两项。`d_c0` 的值中间有一个竖线，形如 `d_c0=AbCd...|1700000000`（有的浏览器复制出来带双引号，带不带都可以）；`z_c0` 是登录令牌。缺任何一个都会被知乎判定为非人类访问（返回 403 或 `need_login`）。
5. `.env` 填入，原样粘贴在等号后面，一行写完，不要加引号：

```
ZHIHU_COOKIE=_zap=xxx; d_c0=xxx|1700000000; z_c0=2.0|xxx; _xsrf=xxx; ...
```

验证：`pixi run doctor` 里"知乎 Cookie 搜索"显示 `直连，实时`。

注意：

- 知乎的请求签名 x-zse-96 由程序在本地计算，不需要你做任何额外操作。
- 搜索结果里会混入广告、热点卡片等非内容条目，程序会自动多取一倍再过滤，所以 `count=8` 实际请求的是 16 条。
- Cookie 过期后自检会报 `HTTP 403` 或 `need_login`，重新复制即可。

### 2.5 小红书（xiaohongshu-mcp）

小红书没有公开接口，本项目通过 [xpzouying/xiaohongshu-mcp](https://github.com/xpzouying/xiaohongshu-mcp) 访问：它内置一个 Chromium 浏览器，用你扫码登录的账号真的去打开搜索页，再把结果经 MCP 协议返回。

**安装（macOS Apple Silicon）：**

1. 到 [Releases](https://github.com/xpzouying/xiaohongshu-mcp/releases) 下载两个文件到同一目录，例如 `~/xhs-mcp/`：`xiaohongshu-login-darwin-arm64`、`xiaohongshu-mcp-darwin-arm64`。GitHub 下载偶尔会被中断，重试即可。
2. 去掉隔离标记并加执行权限：

```bash
cd ~/xhs-mcp && chmod +x xiaohongshu-*-darwin-arm64 && xattr -d com.apple.quarantine xiaohongshu-*-darwin-arm64
```

3. 启动服务（首次会下载约 150 MB 的内置浏览器）：

```bash
cd ~/xhs-mcp && ./xiaohongshu-mcp-darwin-arm64 -headless=false
```

看到 `启动 HTTP 服务器: :18060` 即成功。这个窗口要一直开着，关掉服务就停了。建议用 `-headless=false` 带窗口模式，实测无头模式首次搜索可能卡死。

4. `.env` 填：

```
XHS_MCP_URL=http://localhost:18060/mcp
XHS_MCP_TOKEN=
```

`XHS_MCP_TOKEN` 只在启动时加了 `-token=xxx` 参数才需要，本机自用留空。

**扫码登录：**

```bash
pixi run xhs-login
```

它会调用 MCP 的 `get_login_qrcode` 工具，把二维码存到 `reports/xhs_login_qrcode.png` 并自动打开，用小红书 App 扫一扫，程序每 4 秒检查一次，登录成功会提示。二维码一两分钟就过期，先把 App 开到扫一扫再运行。登录态保存在 `~/xhs-mcp/data/`，重启服务不用重新扫。

验证：`pixi run doctor` 里"小红书 MCP"显示 `已登录 用户名: xxx`。

注意：

- 同一账号不要在其他浏览器里同时网页登录，会把 MCP 的会话顶掉；手机 App 不受影响。
- 关键词不要带空格，程序会自动去掉中文关键词里的空格；带空格会让搜索页等待超时。
- 时政类敏感话题在站内可能搜不到，程序会降级并在报告里注明"疑似被平台限流"。
- Docker 方式见该项目 README，端口同样是 18060，登录仍需按上面的方式扫码。

### 2.6 X

不需要 X 开发者账号。X 搜索复用 2.1 的 Grok Key，通过 xAI Responses API 的服务端工具 `x_search` 完成，返回带原帖链接的帖子。单次最多等 `X_SEARCH_TIMEOUT`（默认 120）秒，超时自动降级。

## 三、自检与排错

```bash
pixi run doctor          # 逐项检查配置与各平台连通性
pixi run doctor --full   # 额外实测 X 搜索链路（消耗一次模型调用）
```

| 现象 | 原因 | 处理 |
|---|---|---|
| LLM 对话 404 `/v1/chat/completions/chat/completions` | `XAI_BASE_URL` 多带了路径 | 填到 `/v1` 为止 |
| LLM 对话 503 `No available channel for model` | 中转站该分组无此模型 | 换分组的 Key 或换 `XAI_MODEL` |
| DeepSeek 401 / 402 | Key 错 / 余额不足 | 重新复制 Key / 充值 |
| 微博搜索报 302 跳转 passport | Cookie 过期或用了手机端 Cookie | 从桌面端 weibo.com 重新复制 |
| 知乎搜索 403 / need_login | Cookie 缺 `d_c0` 或 `z_c0`，或已过期 | 重新复制完整 Cookie |
| 小红书 MCP ConnectError | 服务没启动 | 重新执行启动命令 |
| 小红书 `context deadline exceeded` | 关键词带空格，或话题被限流 | 程序已自动处理，敏感话题会降级 |
| X 搜索超时 | grok-4.7 推理加检索偶尔超过 120 秒 | 自动转 DeepSeek；可调大 `X_SEARCH_TIMEOUT` |
